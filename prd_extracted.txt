Halo
Product Requirements Document
Real-time multi-session video collaboration platform

1. Overview
Halo is a real-time multi-session video collaboration platform. It lets multiple hosts run simultaneous live rooms while an admin or coordinator monitors all sessions from a single cockpit view. The platform is built for education first but is designed to scale into corporate training, healthcare consultations, community events, and any domain that needs coordinated live sessions.
The core idea: instead of opening separate tabs to manage multiple meetings, Halo gives you one unified view where sessions float as live cards, you can jump between them, and AI quietly runs in the background making each session smarter.

2. Problem Statement
The hackathon problem statement (WebRTC domain):
Develop a real-time video collaboration tool for remote learning that enables seamless interaction between students and teachers, with features such as screen sharing, low-latency communication, and multi-class, multi-teacher (multi-session) live streams.

Existing tools like Zoom, Meet, and Teams solve single-session video well. None of them solve the multi-session coordination problem — a school principal, a training manager, or an event organizer cannot monitor and switch between multiple live sessions from one place. That gap is what Halo fills.

3. Goals
3.1 Hackathon goals
Ship a working prototype in 9 hours
Demo 2–3 live simultaneous rooms to judges
Show all four AI features visibly working
Win the WebRTC domain
3.2 Product goals

4. Target Users
4.1 Primary users (hackathon scope)
School administrators managing multiple live classes
Teachers hosting a live class session
Students joining a session to learn
4.2 Future users (post-hackathon)
Corporate L&D teams running parallel training rooms
Healthcare providers running group consultations
Event organizers managing multi-track live events
Community platforms with concurrent topic rooms

5. Core Features
5.1 Multi-session live rooms
Any user can create a named room and become the host
Multiple rooms can be live simultaneously on the same platform
Each room supports video, audio, screen sharing, and chat
Rooms are joinable via a simple link or room code
Screen sharing should support annotation overlay — host can draw on top of shared screen
5.2 Admin cockpit view
A special view showing all active sessions at once
Each session displayed as a live card showing: session name, host name, participant count, duration, and engagement status
Admin can click into any session to see a focused view with individual participant tiles
Admin can join any session directly from the cockpit
Admin can mute all, end session, or send a message from the cockpit without joining
5.3 Screen sharing
Any participant can share their screen with the room
Host can annotate over the shared screen in real time
Shared screen should be low-latency — target under 200ms

6. AI Features
All AI features are powered by Amazon Bedrock (Nova Lite model). They are grouped under a premium tier but should be visibly working in the demo.
6.1 Live subtitles / captions
Real-time speech-to-text for the active speaker in a session
Displayed as a live ticker at the bottom of the session view
Powered by Amazon Transcribe Streaming
Supports Hindi and English in the demo (more languages post-hackathon)
Premium feature — toggle on/off per session
6.2 Attention monitoring
Tracks behavioral signals per participant every 30 seconds
Is the camera on or off
Has the mic had any activity in the last 30 seconds
Is the browser tab visible or hidden (Page Visibility API)
Mouse movement presence
Scores each participant 0–100 based on combined signals
Session-level attention score is an average across all participants
Cockpit view shows color-coded status: green (high), amber (medium), red (low)
If session attention drops below 60% for over 2 minutes, teacher gets a nudge notification
Premium feature — must be enabled by host
Important: no facial recognition or camera image analysis. Only behavioral signals. This is intentional for privacy and reliability.
6.3 Late joiner AI summary
When a participant joins a session that has been running for more than 5 minutes, a summary card appears on their screen
Summary is 3–5 bullet points covering what has been discussed so far
Generated by Bedrock Nova Lite reading the last N transcript chunks stored in S3
Dismissible card — appears once per join
Premium feature
6.4 Post-session AI report
When the host ends a session, an AI report is automatically generated
Report includes: topics covered, participation summary, notable questions asked, suggested follow-up actions
Stored in DynamoDB and accessible from the cockpit after session ends
Can be downloaded or shared
Premium feature

7. UI / UX Direction
This section is intentionally kept rough. The UI should be designed collaboratively — whoever is building the frontend should discuss with the product owner before coding, share visual references or generated images, and agree on the direction first.
7.1 Overall feel
Dark, premium, spatial — not a standard video call UI
Sessions feel like they exist in a space, not a list
Switching between sessions should feel fluid and satisfying
AI features should feel ambient — present but not intrusive
7.2 Key screens
Landing / lobby — create or join a session
Session view — full participant grid, controls, screen share, subtitle ticker
Cockpit view — all live sessions visible simultaneously, switchable
Post-session report view — clean readable report with download option
7.3 Notes for the UI builder
Before starting, discuss the visual direction with the product owner. Ask them if they have reference images, mood boards, or specific ideas. Suggest 2–3 directions and let them pick. Do not start building blind.
The cockpit is the hero screen — it needs to feel like a mission control
Session cards in the cockpit should feel alive — showing real participant thumbnails, live indicators, attention scores
Color language: green = engaged, amber = drifting, red = needs attention
The switch between sessions should be animated and intentional — not just a page reload
Mobile is not a priority for the hackathon — optimize for desktop

8. Technical Architecture
8.1 Frontend
React + Vite
LiveKit React SDK for WebRTC
Deployed as static site on S3 + CloudFront
8.2 WebRTC / real-time
LiveKit for room management, video, audio, screen share
LiveKit server deployed on EC2 (t3.small) via Docker
One EC2 instance handles all rooms
8.3 AI and backend
AWS Lambda for all AI feature endpoints (prefixed mosaic- to avoid VaaniSeva conflicts)
Amazon API Gateway for Lambda endpoints
Amazon Bedrock Nova Lite for: late joiner summary, post-session report
Amazon Transcribe Streaming for live subtitles
Attention scoring is pure logic in Lambda — no LLM needed
8.4 Data
DynamoDB table: halo-sessions (stores session metadata, participant list, reports)
S3 bucket: halo-transcripts-[name] (stores transcript chunks per session)
8.5 Infrastructure notes
All resources named with halo- prefix — completely separate from VaaniSeva
Deployed under its own CloudFormation stack: halo-stack
Same AWS account, zero interference with existing resources
IAM user already exists — just needs Transcribe permissions added if not present

9. Build Order (Hackathon Night)
Strict sequence — do not skip ahead. Each step is a working checkpoint.
EC2 up with LiveKit running. Basic join-a-room working between two browser tabs.
Multi-room working. Three rooms creatable and joinable. 3D cockpit UI dropped in.
Live subtitles via Amazon Transcribe Streaming.
Attention monitoring — Lambda endpoint, frontend polling, scores in cockpit.
Late joiner summary + post-session report. Both Lambda + Bedrock calls.
Demo polish. Three named rooms live. Rehearse the 3-minute demo path.

10. Demo Script (for judges)
Target duration: 3 minutes. Every second counts.
Open the cockpit — three rooms are live simultaneously with real video
Point at History room showing amber attention score — say the AI flagged it
Join the Math room — live subtitles are running at the bottom
Open a new tab, join the same room 10 minutes late — AI summary card appears
End the Science session — post-session report generates and appears in cockpit
Close with: any domain, any scale, the same cockpit

11. Out of Scope (Hackathon)
Mobile app or responsive mobile view
User authentication / login system
Payment / subscription billing
Recording and playback
Facial recognition for attention monitoring
More than 4 AI features
More than 3 simultaneous demo rooms

12. Post-Hackathon Vision
Halo is designed to grow beyond education. The same cockpit, the same AI layer, the same session infrastructure applies to:
Corporate L&D — training managers monitoring parallel onboarding sessions
Telehealth — clinic coordinators overseeing group therapy or consultation rooms
Live events — multi-track conference coordination from one screen
Creator platforms — streamers managing multiple audience rooms
The platform name Halo was chosen intentionally — it signals presence, connection, and a ring that encompasses everything. It does not lock the product into any single domain.
